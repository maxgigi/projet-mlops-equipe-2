# ADR-004
## Titre
- ADR-004 : stockage des artefacts MLflow
- Date : 23/10/2026
- Statut : proposée
## Contexte
Problème, contraintes (ressources, temps, compétences) ?
Le serveur MLflow a besoin d'un stockage pour les artefacts (modèles, fichiers de sortie, etc.). Il faut choisir un stockage adapté à nos besoins, en tenant compte des contraintes de performance, de scalabilité et de compatibilité avec MLflow.
## Options considérées
- Option 1: RustFS (S3-compatible)
    - Avantages : compatible avec MLflow, supporte les opérations S3, facile à déployer localement.
    - Inconvénients : nécessite une configuration et une maintenance, peut être surdimensionné pour de petites installations.
- Option 2: MinIO (S3-compatible)
    - Avantages : compatible avec MLflow, supporte les opérations S3, facile à déployer localement.
    - Inconvénients : la version communautaire n'est plus maintenue activement, certaines fonctionnalités avancées manquent et risque de faille de cybersécurité.
- Option 3: Local filesystem
    - Avantages : simple à utiliser, pas de serveur à configurer, compatible avec MLflow.
    - Inconvénients : limité en termes de performance et de scalabilité, pas adapté pour des installations multi-utilisateurs ou distribuées.
- Option 4: Cloud storage (AWS S3, GCP Storage, Azure Blob)
    - Avantages : scalable, performant, supporte les opérations S3, compatible avec MLflow.
    - Inconvénients : nécessite un compte cloud et une configuration, peut entraîner des coûts supplémentaires.
## Décision
Après avoir évalué les options, nous avons décidé d'utiliser RustFS comme stockage pour les artefacts MLflow. Cette décision est motivée par les raisons suivantes :
- RustFS est compatible avec MLflow et supporte les opérations S3, ce qui facilite l'intégration avec le serveur MLflow.
- Il est facile à déployer localement, ce qui est important pour notre environnement de développement
## Conséquences
On gagnera en performance et en fiabilité, mais il faudra gérer la configuration et la maintenance de RustFS. Il faudra également s'assurer que l'équipe est formée pour administrer ce stockage.
## Plan B
Si la configuration de RustFS est trop complexe pour notre équipe, nous pourrions envisager d'utiliser un stockage local pour les artefacts MLflow. Cependant, cela pourrait entraîner des limitations en termes de performance et de scalabilité.
