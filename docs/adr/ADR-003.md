# ADR-003
## Titre
- ADR-003 : base de données pour MLflow
- Date : 23/10/2026
- Statut : proposée 
## Contexte
Problème, contraintes (ressources, temps, compétences) ?
Le serveur MLflow a besoin d'une base de données pour stocker les métadonnées des expériences et des modèles. Il faut choisir une base de données adaptée à nos besoins, en tenant compte des contraintes de performance, de scalabilité et de compatibilité avec MLflow.
## Options considérées
- Option 1 : PostgreSQL
    - Avantages : robuste, performant, supporte les transactions, compatible avec MLflow.
    - Inconvénients : nécessite une configuration et une maintenance plus complexes, peut être surdimensionné pour de petites installations.
- Option 2 : MySQL
    - Avantages : populaire, facile à configurer, compatible avec MLflow.
    - Inconvénients : moins performant que PostgreSQL pour certaines charges de travail, certaines fonctionnalités avancées manquent.
- Option 3 : SQLite
    - Avantages : simple à utiliser, pas de serveur à configurer, compatible avec MLflow.
    - Inconvénients : limité en termes de performance et de scalabilité, pas adapté pour des installations multi-utilisateurs ou distribuées.
## Décision
Après avoir évalué les options, nous avons décidé d'utiliser PostgreSQL comme base de données pour MLflow. Cette décision est motivée par les raisons suivantes :
- PostgreSQL est robuste et performant, ce qui est important pour gérer les métadonnées des expériences et des modèles.
- Il supporte les transactions, ce qui garantit l'intégrité des données.
## Conséquences
On gagnera en performance et en fiabilité, mais il faudra gérer la configuration et la maintenance de PostgreSQL. Il faudra également s'assurer que l'équipe est formée pour administrer cette base de données.
## Plan B
Si la configuration PostgreSQL est trop complexe pour notre équipe, nous pourrions envisager de passer à une base donnée Sqlite en local pour les tests et le développement. Cependant, cela pourrait entraîner des limitations en termes de performance et de scalabilité.
